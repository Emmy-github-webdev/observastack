# 6.9 Secrets — Integration Notes

## Environment root

The environment root should compose the module rather than duplicate its implementation.

```hcl
module "secrets" {
  source = "../../modules/secrets"

  project_name = "observastack"
  environment  = "staging"
  kms_key_arn  = module.kms.key_arn

  recovery_window_in_days = 14

  secrets = {
    "applications/user-service" = {
      description = "User service credentials"
    }
    "applications/product-service" = {
      description = "Product service credentials"
    }
    "applications/order-service" = {
      description = "Order service credentials"
    }
    "applications/payment-service" = {
      description = "Payment service credentials"
    }
    "integrations/stripe" = {
      description = "Payment provider integration credentials"
    }
  }

  rds_master_user_secret_arn = module.rds.master_user_secret_arn
  redis_auth_secret_arn      = module.redis.auth_secret_arn
}
```

## Dependency order

```text
VPC
 │
 ├── KMS
 │    │
 │    ├── RDS
 │    ├── Redis
 │    └── Secrets Manager
 │
 └── EKS/IAM
       │
       └── External Secrets / Pod Identity
```

The application secret metadata can be created before application workloads are deployed. Workload access should not be granted until the exact secret ARNs are known.

## Tightening the External Secrets IAM policy

The 6.4 IAM module initially used an environment-wide pattern:

```text
arn:aws:secretsmanager:*:*:secret:observastack/<environment>/*
```

After 6.9, prefer exact ARNs generated by this module. For example:

```hcl
resources = [
  module.secrets.secret_arns["applications/user-service"],
  module.secrets.secret_arns["applications/product-service"],
]
```

This is the intended end state for least privilege.

## Secret value bootstrap

Do not add:

```hcl
resource "aws_secretsmanager_secret_version" "example" {
  secret_string = var.password
}
```

for production application credentials in this module. The value would be represented in Terraform state.

Instead, use a controlled bootstrap mechanism such as an approved CI/CD release step or an administrative procedure to write the value to the already-created secret.

## Kubernetes consumption

The Terraform module does not create `ExternalSecret`, `SecretStore`, or `ClusterSecretStore` resources. Those belong in:

```text
gitops/
kubernetes/platform/external-secrets/
```

or the repository's agreed GitOps layout.

The AWS IAM role should use EKS Pod Identity and be scoped to exact secret ARNs.
